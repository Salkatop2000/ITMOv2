# Logic Specification (extract)

Контекст: CLI-команда `search` в `src/task_cli.py`.

- Данные: JSON-массив задач `{ id, title, status }` из `data/tasks.json`.
- Алгоритм:
  1. Принять `--query` (строка после trim длиной 1..256) и `--status` (open|done|all).
  2. Валидация: если после trim длина <1 или >256 — вернуть ошибку (stderr) и код возврата 2.
  3. Загрузить задачи; применить фильтр по статусу (если указан, иначе все).
  4. Сопоставление: регистронезависимое contains по `title`.
  5. Порядок: сохранить порядок списка (текущий по id asc).
  6. Вывод: строки в формате `<id> | <status> | <title>`; пустой результат — «No tasks.».
- Правила: спецсимволы — литералы; без regex/stemming; поиск поверх активных фильтров, без изменения сортировки.
- Ошибки: валидационная ошибка длины; `invalid_query` для пустого запроса; недопустимый статус фильтруется парсером аргументов.
- Обратная совместимость: формат данных и поведение существующих команд не меняются.

Согласовано на основе `specs/001-task-search-by-title/spec.md` и `.../COMMON_CONTRACT.md`.
