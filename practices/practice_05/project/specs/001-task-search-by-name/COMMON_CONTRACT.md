# Common Contract: Task Search

## Human-approved decisions

1. Empty query
- Пустой query не отправляется в search API.
- При очистке поиска UI напрямую возвращает исходный список.
- Активные фильтры и текущая сортировка при этом сохраняются.
- `invalid_query` для пустого query не является пользовательским сценарием поиска.

2. Matching
- В v1 поддерживается только поиск по подстроке (contains).
- Режим `exact` исключён из v1.
- Поиск регистронезависимый.

3. Normalization
- Для v1 используется trim + сравнение без учета регистра.
- Collapse внутренних пробелов не является обязательным поведением v1.
- Не добавлять regex, stemming, synonyms или другие формы fuzzy search.

4. Query length
- Максимальная длина query — 256 символов.
- Ограничение согласовано между UI и logic boundary.
- Слишком длинный query приводит к явной validation error.
- Не добавлять дополнительные правила обработки сверх этого решения.

5. Filters
- Поиск применяется поверх всех существующих активных фильтров.
- Поиск не должен сбрасывать фильтры.
- Не ограничивать контракт только `status`, если существующий UI поддерживает дополнительные фильтры.

6. Sorting
- Поиск сохраняет существующую сортировку списка.
- API не должен принудительно менять сортировку на `id ascending`, если текущая сортировка иная.
- Не добавлять новый параметр `sort` только ради поиска, если он не нужен текущей архитектуре.

7. Result shape
- Минимальный контракт результата: список задач с `id`, `title`, `status`.
- `meta` не является обязательной частью v1 API-контракта.

8. Error mapping
- UI должен показывать понятное состояние ошибки поиска и кнопку «Повторить».
- Ошибка валидации слишком длинного query отделена от обычной ошибки выполнения поиска.
- Empty query не должен попадать в API.
- Не добавлять новые типы ошибок без необходимости.

9. Clear search
- Кнопка очистки и Esc очищают query.
- После очистки UI восстанавливает обычный список.
- Активные фильтры и сортировка сохраняются.
- Для этого не нужно вызывать search с пустым query.

## UI contract
- query/input behavior: поиск начинается при вводе не пустой строки (после trim); пустой query не инициирует поиск.
- debounce: короткая задержка перед отправкой запроса.
- clear: кнопка «Очистить» очищает поле и возвращает исходный список без вызова поиска.
- Esc: клавиша Esc очищает поле и возвращает исходный список.
- loading: индикатор загрузки (скелетон/спиннер) в области результатов на время поиска.
- empty: явное состояние «Нет задач по запросу “…”» + кнопка «Очистить поиск».
- error: компактный блок ошибки «Не удалось выполнить поиск».
- retry: кнопка «Повторить» перезапускает последний запрос.
- сохранение фильтров: активные фильтры сохраняются и используются в поиске.
- сохранение сортировки: используется текущая сортировка списка, поиск её не меняет.

## Logic/API contract
- query: строка после trim длиной 1..256 символов; пустой query не является поисковым запросом в v1.
- normalization: trim + сравнение без учета регистра; collapse внутренних пробелов не обязателен.
- max length: 256 символов; превышение приводит к validation error.
- contains matching: единственный режим сопоставления в v1 (подстрока, регистронезависимый).
- filters: поиск выполняется поверх активных фильтров списка; контракт не ограничивается одним `status`, интеграция повторяет фильтры листинга.
- sorting: поиск не изменяет текущую сортировку; не навязывает `id ascending`; новый параметр `sort` не добавляется в v1.
- result fields: массив `Task { id, title, status }`.
- validation errors: отдельный тип для слишком длинного запроса (валидационная ошибка).
- execution errors: ошибки выполнения/сети обрабатываются на уровне клиента стандартным образом; типизация без избыточного расширения.

## End-to-end contract
1. Пользователь находится на списке задач.
2. Вводит поисковый запрос.
3. UI выполняет поиск после debounce (если query не пустой и длиной ≤ 256 после trim).
4. Logic применяет query поверх активных фильтров.
5. Результаты отображаются с существующей сортировкой.
6. Пользователь может перейти к задаче обычным способом.
7. При отсутствии результатов показывается empty state.
8. При ошибке показывается retry.
9. При очистке поиска восстанавливается исходный список с сохранением фильтров и сортировки.

## Out of scope for v1
- exact match.
- regex.
- stemming.
- synonyms/fuzzy search.
- изменение хранилища данных.
- изменение существующих команд.
- обязательная metadata в response.
- новый механизм сортировки или новый параметр `sort` специально для поиска.

## Compatibility
- Поведение существующего Task Tracker не должно ломаться: поиск не сбрасывает фильтры и сортировку; формат хранилища и существующие команды остаются без изменений; новый контракт поиска интегрируется в текущий пайплайн листинга без регресса.
