## Context Pack для первого рабочего сценария

### Факты и правила

- POST /api/reviews ожидает тело с ключом `diff: str` и возвращает `{"comment": str}`.
- Валидации входа и типизированной схемы нет, из-за этого неверный вход ведёт к 500.
- Вызов LLM синхронный; исключения не ловятся.

### Формат входа и результата

- Вход: JSON `{ "diff": "<git diff text>" }` как строка.
- Результат: JSON `{ "comment": "<review text>" }`.

### Ограничения и запрещённые действия

- Нельзя выходить за рамки предоставленных файлов; нельзя выдумывать наличие доп.кода.
- Нельзя сохранять или логировать полный diff в проде; только метаданные.
- Нельзя выполнять LLM без таймаутов и лимитов на длину входа в проде — зафиксировано как требование TO BE.

### Хороший пример


Запрос:

```
POST /api/reviews
{"diff": "diff --git a/app/x.py b/app/x.py\n..."}
```

Ответ:

```
{"comment": "Found missing validation and error handling"}
```

### Плохой пример


Запрос без ключа `diff` или с `diff: 123` (не строка) — приводит к 500 в текущей реализации.

### Что пока неизвестно

- Ограничения длины diff, ожидаемые SLA, политика логирования.
- Требования к форматированию ответа и локализации.
